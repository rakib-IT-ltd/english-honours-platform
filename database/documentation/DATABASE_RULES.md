# Database Rules

> **Status:** conventions fixed so far. Extended with the first data model.

- The schema lives in `database/prisma/schema.prisma`; migrations in `database/prisma/migrations`.
  Only the API accesses the database.
- Model proper relationships (foreign keys); academic data is database-driven, never hardcoded in UI.
- Support multiple universities, academic sessions and syllabus versions from the first model.
- Content records carry author, reviewer, references, status, version and correction history.
- Seed data is either official verified data with a recorded source, or clearly labelled sample data
  for development/testing only. Never fake academic content in production.

## Rules added with Module 1

- Primary keys are UUID strings generated by Prisma. Foreign keys are `ON DELETE RESTRICT`.
- Bangla fields (`nameBn`) are nullable: unreviewed Bangla text must never be forced in.
- `yearNumber` is CHECKed to 1..4 and `endYear >= startYear` in the migration SQL (Prisma cannot
  model CHECK constraints, and ignores them when diffing).
- A syllabus's session and academic year must belong to the same university. This spans tables, so
  the service that writes syllabuses must enforce it (writes arrive with the admin module).
- A syllabus is `VERIFIED` only through `SyllabusesService.verify`: at least one `SyllabusSource`
  is required and a `SyllabusVerification` row is written in the same transaction.
- Migrations are committed SQL. After editing `schema.prisma`, create migrations with
  `pnpm db:migrate`; never edit an applied migration.
