# Database Rules

> **Status:** conventions fixed so far. Extended with the first data model.

- The schema lives in `database/prisma/schema.prisma`; migrations in `database/prisma/migrations`.
  Only the API accesses the database.
- Model proper relationships (foreign keys); academic data is database-driven, never hardcoded in UI.
- Support multiple universities, academic sessions and syllabus versions from the first model.
- Content records carry author, reviewer, references, status, version and correction history.
- Seed data is either official verified data with a recorded source, or clearly labelled sample data
  for development/testing only. Never fake academic content in production.

## Rules added with Module 1

- Primary keys are UUID strings generated by Prisma. Foreign keys are `ON DELETE RESTRICT`.
- Bangla fields (`nameBn`) are nullable: unreviewed Bangla text must never be forced in.
- CHECK constraints live in migration SQL (Prisma cannot model them, and ignores them when diffing):
  `endYear >= startYear`, `AcademicLevel.sequence >= 1`, and `University.code` is a lowercase
  URL-safe slug.
- A syllabus's program and session must belong to the syllabus's university, and its program must
  offer its level. This is enforced by the database through composite foreign keys
  (`(id, universityId)` unique keys on Department, AcademicSession, AcademicProgram; `ProgramLevel`).
  `Syllabus.universityId` is denormalised on purpose to make this possible.
- `AcademicLevel` rows are shared reference data (five rows), not per university. Never duplicate
  them per university. Everything else university-specific hangs off `University`.
- Constraint names longer than PostgreSQL's 63-character limit get an explicit `map:` name.
- A syllabus is `VERIFIED` only through `SyllabusesService.verify`: at least one `SyllabusSource`
  with `sourceType = OFFICIAL_UNIVERSITY_DOCUMENT` is required and a `SyllabusVerification` row is written in the same transaction.
- Migrations are committed SQL. After editing `schema.prisma`, create migrations with
  `pnpm db:migrate`; never edit an applied migration.
- At most one `Syllabus` per (program, level, session) may have `isCurrent = true`: a partial unique
  index in the migration SQL (Prisma ignores it when diffing).
- The only seed is `database/prisma/seed/universities.sql` (names only, idempotent, development use).
  Syllabus, course and session data are never seeded from memory.
